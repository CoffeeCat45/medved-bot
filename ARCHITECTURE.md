# Архитектура проекта «Медведь онлайн»

## Общий поток данных

```
+--------------------------------------------------------------+
|                     Frontend (React)                         |
|  App.tsx -> Step1/Step2/Step3 -> FinalScreen -> HistoryScreen|
+--------------------------------------------------------------+
                              |
                              | HTTPS, заголовок Authorization: Bearer
                              v
+--------------------------------------------------------------+
|                     Backend (FastAPI)                        |
|                                                              |
|  /api/auth/me --------> CORE-сервис (ЕСИА) -> обрезка ПДн    |
|                                                              |
|  /api/check-symptoms --> safety.py --> red_flags.yaml        |
|                                                              |
|  /api/triage:                                                |
|     1. safety.py (Red Flags) -> прерывание при экстренности  |
|     2. GigaChat -> классификация категории жалобы            |
|     3. router.py -> категории и модификаторы                 |
|     4. TriageResult -> JSON                                  |
+--------------------------------------------------------------+
```

## Слой 1: критические состояния (core/safety.py, rules/red_flags.yaml)

Принцип: детерминированные правила выполняются до любого обращения к нейросети. Нейросеть не имеет права понижать срочность обращения.

Функции слоя:

- нормализация текста (нижний регистр, замена «ё» на «е», схлопывание пробелов);
- числовой разбор температуры, включая запись через запятую («39,8»);
- определение детского контекста по флагу `is_child` и по словам «ребёнок», «сын», «дочь» в тексте;
- приоритетный перебор правил из YAML-файла.

Возвращаемая структура: `SafetyResult(is_emergency, instruction, matched_rule)`.

При `is_emergency = True` маршрутизатор немедленно возвращает карточку «Скорая помощь / Экстренно» без дальнейших вычислений.

## Слой 2: резервный NLP (core/nlp.py)

Используется только при недоступности GigaChat (таймаут более 8 секунд или сетевая ошибка). Выполняет keyword-matching по категориям жалоб.

## Слой 3: LLM (core/llm_client.py)

Модель: GigaChat (Сбер), scope `GIGACHAT_API_PERS`.

Функции слоя:

- получение OAuth2-токена с кэшированием в памяти процесса (срок жизни 30 минут);
- обращение к эндпоинту чат-комплитов;
- разбор JSON-ответа и валидация категории по whitelist.

Ограничения слоя:

- не ставит диагноз;
- не определяет срочность (только категорию жалобы);
- не получает данные о сработавших Red Flags.

## Маршрутизатор (core/router.py)

Правила из `triage_rules.yaml` применяются в фиксированном порядке:

1. Экстренное перекрытие — если сработал Red Flag.
2. Базовая категория: специалист, место, срочность.
3. Локализация: уточнение специалиста для категории «боль».
4. Хронические заболевания: повышение срочности.
5. Анамнез: операции за год, наследственность, курение, аллергии, лекарства.
6. Ключевые слова затяжного течения («третий день», «усиливается»).
7. Модификаторы ребёнка и беременности.
8. Политика мест обращения: телемедицина и аптека доступны только при низкой срочности.
9. Тип оплаты: учитывается только при срочности «Планово» или «Самопомощь».
10. Рекомендации по самопомощи: уход без указания препаратов и дозировок.

Ключевая функция `_raise`: уровень срочности может быть только повышен, никогда не понижен. Это основная защита от формирования опасных рекомендаций.

## API-эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка работоспособности сервиса |
| POST | `/api/check-symptoms` | Проверка текста на критические состояния |
| POST | `/api/triage` | Финальная маршрутизация пациента |
| GET | `/api/auth/me` | Профиль пользователя (имитация ЕСИА) |
| POST | `/api/parse-text` | Извлечение категории и локализации (NLP) |
| POST | `/api/llm-classify` | Классификация жалобы через LLM |

## Хранение данных

- Серверная база данных отсутствует (осознанное решение в рамках ФЗ-152).
- История обращений хранится в `localStorage` устройства пользователя, ключ `medved_history_v2`.
- СНИЛС и номер полиса ОМС обрезаются на backend и не передаются во frontend.
- JWT-токен извлекается из URL при загрузке страницы и немедленно удаляется из адресной строки; срок жизни токена — 5 минут.
